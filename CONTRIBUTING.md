# Contributing

Keep PlanOnce small, testable, and provider-neutral.

1. Add or change behavior through a failing repo-contract/eval test first.
2. Keep `SKILL.md` concise; move detail to `references/`.
3. Do not add another user-facing skill unless the six-workflow model genuinely cannot express the need.
4. Preserve Plan Once, human gates, plan-amendment, and evidence-before-completion invariants.
5. Run all validation commands in `AGENTS.md` before submitting a PR.
